# Optional coach identity verification — 7 October 2026

The local implementation adds a head-coach image tool and extends presentation preferences with name/avatar inputs. Athlete opt-in is off by default and cannot be changed through the tool. Identity is peripheral to coaching, explained through a progressive skill and a short constitution/product-map addition.

Image generation is independent of conversation vision. Google Gemini generateContent and OpenAI-compatible Images adapters share `ImageProvider`. Keys remain in the trusted server, never tool schemas or sandbox environments. These adapters were implemented against official API references and tested with controlled responses. No live image provider request or generated-image quality evaluation was performed; no new image credentials were supplied.

Contract checks cover square request bodies, header-only keys, disabled/missing configuration, output decoding, filtered/malformed images, response bounds, redirection refusal, sanitized errors and cancellation. Runtime checks cover permission/self-grant/helper/automatic-turn denial, name-only operation without generation, private owned blobs, separate generation/application, exact replay, uncertain-attempt markers, serialized budget reservations, invalid raster output and in-flight permission revocation. Image attempts are conservatively charged before dispatch; this is an operator estimate, not provider invoice reconciliation.

A Chromium test uses synthetic raster bytes returned by a mocked provider through the production adapter and tool executor. It opts in through the real PWA/gateway, generates without applying, applies a saved name/avatar, observes the 512px authenticated image, reloads, checks anonymous access is denied, resets the avatar and revokes permission. Browser fixtures use a separate temporary deployment and are cleaned up. The installed athlete's actual identity is not changed by testing.

The UI falls back to initials for absent, failed or invalid blob references. Settings includes permission, reset and image-service availability; name/avatar updates refresh through the existing settings WebSocket event. Changes follow the account across devices. The existing private blob export/delete lifecycle includes generated images, with image-attempt namespace cleanup scoped to the deleted athlete. Existing workspace notes and published screens are preserved.

Validation logs are stored locally under `work/identity-*.log`; build and aggregate typecheck passed, as did 790 core tests plus 3 renderer gates, 147 web unit tests and 24 Chromium browser tests, and the 25-case fast reference suite (32 assertions, zero failures/missing evidence). The offline self-test passed positive and negative controls. The initial core run exposed a static skill-catalog list needing the new skill; the initial browser assertion assumed an asynchronous switch saved immediately. Both checks were corrected and rerun; model/provider failures were not retried until green.

Image generation is disabled unless configured separately. The coach's situation report states that limit and distinguishes generation from visual inspection. Name changes work after athlete opt-in; generated avatars require a dedicated configured image key. Guidance in a frozen epoch refreshes on the next epoch, while the current situation/tool docs already point to the new skill.
